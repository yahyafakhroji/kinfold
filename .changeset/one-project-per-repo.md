One repo is one project. Kinfold keeps each repo's first commit, so a renamed remote, a fork and a clone with no remote merge into the newest key with a remote, on their own, and an upgraded store does this once for the projects it already holds. `kinfold status`, `kinfold watch` and the install output say each merge once. `kinfold project list` shows each key with its counts, `kinfold project split <key>` undoes a merge exactly and keeps the key apart, and `kinfold project merge <old> <into>` joins a folder git cannot match. Merge and split are dry runs without `--yes`, and run on the hub in central mode. A session resumed after its remote was renamed moves to the new key, so the prompt line, the turn end, watch and Sessions name one project.
