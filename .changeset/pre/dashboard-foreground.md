BREAKING: the dashboard is closed unless `kinfold dashboard` is running. The command now stays in the foreground: it opens your browser already signed in and prints a live log of the dashboard's requests (method, path, status, time) and of steps such as a sign-in, a backup, a restore or a settings change. Ctrl-C, closing the terminal or SIGTERM signs out the pages it opened and prints "Signed out; the dashboard is closed." A command that is killed stops renewing its lease, and the dashboard closes within 15 seconds. Several `kinfold dashboard` commands can run at once; each signs out only its own pages. The browser opens at the plain address `http://127.0.0.1:<port>/dashboard/login` on macOS, Linux and Windows, and the page claims the sign-in the running command offered: once, within 60 seconds, and only from the dashboard's own origin. No code or token appears in a URL, a process's arguments or the terminal. `kinfold dashboard --print` prints a link for a script or a browser through an SSH tunnel and keeps the dashboard open for 12 hours or until `kinfold dashboard --close`. An open page whose own command ended shows "Dashboard closed; run `kinfold dashboard` to open it again", even while another `kinfold dashboard` keeps the dashboard open. Capture, recall, central memory and the hub keep running either way, and the dashboard stays signed in through an update's daemon restart.
