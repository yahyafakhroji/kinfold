# kinfold

## 0.6.0-beta.0

### Minor Changes

- f3e3add: One memory for all your devices over Tailscale. `kinfold central serve` makes a machine the hub, and `kinfold central join <hub> <code>` points a device at it: the device's agents then capture into and recall from the hub's memory. Joining copies in the projects the hub lacks and leaves the device's own memory as it was. Only nodes of the hub's own Tailscale user can pair; each device signs every request with its own key, can read and capture, and leaves purge, retention, backup, restore, encryption and observer settings to the hub. Captures wait on the device while the hub is away. `kinfold central devices`, `remove`, `invite`, `leave` and `import --project` manage it, and `kinfold status` and the dashboard show the mode.
- c8a84e1: Semantic search runs on a bundled local model by default: all-MiniLM-L6-v2 on your CPU, free, offline, with no memory text leaving the machine. OpenRouter and a local LLM server on loopback (Ollama, LM Studio) are opt-in, picked in the wizard, with `--embeddings`, or on the dashboard's Models page. Search goes through a per-project sqlite-vec index, and switching embedders builds the new index in the background while search keeps the old one. A store that already has OpenRouter vectors stays on OpenRouter until you switch. The program is about 36 MB larger.
- fe1b38b: More observer providers. API providers with your own key: `anthropic-api`, `openai-api`, `gemini-api`, `qwen-api` (DashScope) and `openai-compatible` for any OpenAI-style server, including Ollama and LM Studio on this machine with no key. `goose-cli` runs the observer through a provider key you gave Goose, after the same planted-instruction safety check as Codex and OpenCode. Setup says why an agent's own CLI cannot run its summaries, lists Auggie, which cannot be picked until a live run proves it safe, and takes `--observer-endpoint <url>` for the endpoint providers. The dashboard Models page offers every provider with its key entry and address.
- cf479c0: Updates have three levels, `off`, `notify` and `patch` (the default), set with the wizard, `kinfold install --updates <level>` or the dashboard. At `patch`, a minor or major release is downloaded and checked against `SHA256SUMS` in the background, then offered once at session start (`Kinfold 0.6.0 is ready · 3 changes, 1 breaking · kinfold update to install`) and on the dashboard with its changelog lines and an Install button. Nothing bigger than a patch installs without your yes. `--beta` offers prereleases the same way. Existing installs keep their choice: update check off is `off`, auto-update off is `notify`, anything else is `patch`.
- cf479c0: BREAKING: Update notices no longer go into an agent's model context. Agents with a user line (Claude Code, Codex, Gemini CLI and others) still show them, OpenCode and Kilo Code show them as a toast, and Copilot CLI on its progress line. Cursor, Cline, Kiro, Antigravity and the other agents with no user line leave them to `kinfold status`, the dashboard and `kinfold watch`, which now prints the notice once.
- cab9513: `kinfold watch --debug` shows why each recall came out as it did: how long the hook waited and whether the daemon answered in time, the search (keyword or meaning, the embedding model, the prompt's terms), each candidate with its distance and matched terms and why it was sent or left out, the new memory from other sessions, and the tokens sent. At a Claude Code turn end it prints the turn's usage from the transcript beside the tokens Kinfold added, and it shows each observer run and each session-start pack. `--json` prints one JSON object per event. The daemon records the trace only while a debug watch is connected, keeps it in memory only (the last few hundred events, gone after a restart), and the prompt hook makes no extra request for it.

### Patch Changes

- cab9513: A dashboard session now survives a daemon restart, so pressing Install on the dashboard no longer ends at the sign-in page. Sessions are kept in `dashboard-sessions.json` in the data folder (mode 0600, holding only hashes of the session secrets), keep their 12-hour expiry and sign-out, and are removed on uninstall. With the beta channel on, a newer beta no longer holds back the automatic patch of the running release: the daily check keeps the newest patch of the running version beside the release on offer, installs the patch under `patch`, and still waits for a yes on the beta.
- 86f2852: WSL: every agent's wiring in a linked distro is now tested, with its hooks writing into the Windows memory and its recall line coming from the Windows daemon and its recall toast reading the Windows folder. A new CI job installs the built programs on a Windows runner and runs the Linux build in an Ubuntu WSL2 distro. WSL stays in preview because GitHub's Windows runners refuse mirrored networking, so the hop from the distro to the Windows daemon is checked by fakes only.

## 0.5.0

### Minor Changes

- 20448a8: Everything merged since 0.4.0:
  
  - See what Kinfold recalls. After each prompt the agent shows a line naming the memories Kinfold sent, and a session starts with a short list of recent memories. This goes through `systemMessage` in Claude Code, Codex, Gemini CLI, Qwen Code, Factory Droid, Junie and Auggie, a toast in OpenCode and Kilo Code, a notification in Amp and the progress line in Copilot CLI. `kinfold watch` prints the recall line for every agent.
  - The dashboard has a Sessions page with each turn's prompt, recalled memories, reply and saved memories. Replies are stored in `prompts.reply_text` and follow prompt retention.
  - Metrics shows the tokens Kinfold adds to context, observer tokens and embedding calls. An opt-in impact test (`--holdout`) skips recall on about 1 in 10 Claude Code prompts and compares token use.
  - The observer can be turned off per agent (`--observer <agent>=off`, the wizard or the dashboard), and the wizard's observer question offers only CLIs installed on this machine.
  - `kinfold restore --undo` switches back to the store a restore replaced, keys included, and the Backup page offers the same.
  - Kilo Code captures again, with its own plugin and a recall toast. The plugin Kinfold wrote for Kilo before was refused by Kilo, so nothing was captured from it.
  - Fixes: a second CLI restore refuses at once, uninstall and first install take the update lock, purge removes `turn_usage` rows, late answers are recorded and left out of the counts, and `kinfold status` gives macOS bash users the line to add when there is no `~/.bash_profile`.
  - Migrations 12 and 13. Backups made by this version carry schema 13, which older versions refuse; older backups restore here.
- 20448a8: `kinfold size` and the dashboard Data page break the store down by part: prompts, replies, events, observations, summaries, vectors and other. Past the size warning, a line names the largest part and the setting that trims it, such as `warning: replies are 61% of 2.1 GB; set prompts retention to trim them`. Release notes now carry the version's CHANGELOG.md section, and releases come from changesets and wait for the maintainer's approval.
