# kinfold

## 0.6.1

### Patch Changes

- 67f4a4b: The remaining fixes from the 0.6.0 audit. Most of them make Kinfold do less work; these are the ones you may notice.
  
  `kinfold findings --purge <id>` finds a pending finding however old it is. It looked only at the newest 100, so after a rules update with hundreds of findings an older one read as "no pending finding".
  
  `kinfold uninstall` names only the key store entries that exist. It printed a "kept keychain entry" line, with a delete command, for every provider Kinfold knows.
  
  `kinfold install` checks a port you type, and asks again when another program holds it. It starts each agent's CLI once to read its version, a few at a time, where it started each one twice and one after another. If you or an agent save a config file (`~/.claude/settings.json`, `opencode.json`, a shell startup file) while the install runs, the install stops at that file and asks you to run it again; before, it wrote its own copy over your change.
  
  The dashboard's Overview and Impact pages show a purge or a retention change at once. They kept the old counts for up to ten minutes. A browser now keeps the dashboard's script and style files between visits.
  
  A backup is flushed to disk before `kinfold backup` reports it, and a backup whose worker stops answering fails after 30 minutes with an error.
  
  In OpenCode and Kilo, a session still in use keeps its memory after the plugin has seen more than 256 sessions. The plugins tell the daemon about new events once per burst, not once per event.
  
  On a hub, a paired device can no longer attach a memory to another device's session through an import.
  
  After you replace an observer key, events that had failed retry within two minutes. The daemon asked the key store every 30 seconds until then, which on macOS starts a program each time.
  
  Also: `kinfold scan`, `kinfold watch` with a filter, and a long Claude Code turn with the impact test on no longer hold the daemon's attention for seconds; the daemon stops cleanly when `daemon.json` is unreadable; a new index (schema 20, added on first start) speeds up the MCP timeline; and the release workflows pin each GitHub Action to a commit.
- 2fb269c: Fixes from the 0.6.0 audit for stalls and wrong results.
  
  The daemon answers while it works through a backlog. After a sleep or a restart it stored every waiting capture in one go, before it listened for requests; now it starts answering first and stores 200 captures at a time, with requests served in between. It asks git for a folder's project once per batch and before it opens the write, a folder whose git times out is asked again after 30 seconds and no longer once per capture, and MCP reads skip the walk through a repo's history.
  
  Retention deletes old memories and summaries 500 at a time, up to 10,000 per run, and the next run 10 minutes later carries on. Tightening retention on a long history used to delete everything in one write and could hold the daemon for seconds. Deleting memories is faster on a large store too: a new index (schema 19, added on first start) removes a full scan per deleted memory, and the dashboard's metrics page reads its turn times through an index and reuses a summary for 30 seconds.
  
  Capturing a long single line (a base64 blob, a minified bundle, a long dotted name) no longer hangs the capture hook. Redaction took seconds to minutes on such lines, the agent killed the hook and the event was lost. It finds the same secrets as before, with one limit: a key name that runs on for more than 256 characters after the word `token`, `password` and the like no longer counts as a key name.
  
  Search results that match any term can be paged. Page 2 of such a search came back empty under the heading "matched every term".
  
  `sh install.sh --observer-token-stdin` reads the token you pipe in. On a machine with a terminal it read the terminal and dropped the piped token.
  
  `kinfold uninstall` no longer stops when one agent's config file is not valid JSON. It leaves that file alone, prints `<agent>: skipped; <file> is not valid JSON`, and still removes the service, the other agents' wiring and the program.
  
  In OpenCode and Kilo, a session that started while the daemon was down could stay without its memory pack until the next compaction, and text from before a compaction could reappear after it. A restore started during an embedding change now waits for it and no longer opens the store twice. The observer is shown the 40 memories a long session received last, so it stops saving restatements of them as new. Background indexing no longer stalls for good when the local embedding worker exits without an error.
- e374e0b: BREAKING: security fixes from the 0.6.0 audit. Four things you may notice. A new install checks for updates daily and tells you, and installs nothing by itself: releases are not signed yet, so `patch` is now a choice (`kinfold install --updates patch`) and an install already at `patch` keeps it. `kinfold central join <hub>` asks for the pairing code or reads it from stdin; the code still works on the command line and in `kinfold install --central-code`, with a warning, since other programs on the machine can read a command line. The daemon makes a new token at every start, so a script that saved `daemon.token` must read it again. `KINFOLD_SQLITE3MC_LIB` is read only under `NODE_ENV=test`.
  
  `kinfold project merge` and `kinfold project split` work again; the daemon answered 400 to every request.
  
  `kinfold dashboard` signs in only the browser it opened. The command makes a one-time secret, and a sign-in without it gets nothing, so another program on the machine can no longer take the session by asking first. If the browser has not signed in after a few seconds, the command prints the address to open by hand. A page on another 127.0.0.1 port can no longer trigger a backup download, use up the update banner or call the hub with your dashboard session.
  
  Kinfold no longer keeps the contents of a sensitive file an agent writes or edits (`.env`, `*.pem`, `id_rsa` and the like), or a command that names such a file; before, it withheld only the output. The secret scan now flags rows stored before this fix, so you can redact them. A private key cut off before its END line is redacted too.
  
  A memory title containing the word "constructor" no longer stops that project's session-start memory from updating.
  
  Also fixed: an observer setting could send the Claude login token to another provider's address; the observer followed redirects; clients sent the daemon token to whatever held the port after a crash; purge and redaction left a copy of the embedding in the search index; restore accepted a backup with database triggers or a damaged database; the hub read a request body before checking who sent it; a device name could carry terminal control characters; install could loosen a locked OpenCode folder; three downloads had no size limit while downloading; the port picker and the printed status command trusted input they should not.
- cec4d3e: On Windows, the daemon keeps answering while it drops an old embedding index after you switch embedding models. Vectors upkeep and the indexer now wait while the store is being checkpointed: a write on the daemon's thread waited behind each checkpoint, and on a Windows CI runner it held the thread for 2.4 to 3.7 s.
  
  Also: the daemon waits up to 10 s for its checkpoint worker to close when it stops, so a slow last checkpoint no longer leaves the store file open on Windows.

## 0.6.0

### Minor Changes

- f3e3add: One memory for all your devices over Tailscale. `kinfold central serve` makes a machine the hub, and `kinfold central join <hub> <code>` points a device at it: the device's agents then capture into and recall from the hub's memory. Joining copies in the projects the hub lacks and leaves the device's own memory as it was. Only nodes of the hub's own Tailscale user can pair; each device signs every request with its own key, can read and capture, and leaves purge, retention, backup, restore, encryption and observer settings to the hub. Captures wait on the device while the hub is away. `kinfold central devices`, `remove`, `invite`, `leave` and `import --project` manage it, and `kinfold status` and the dashboard show the mode.
- ab2b658: BREAKING: the dashboard is closed unless `kinfold dashboard` is running. The command now stays in the foreground: it opens your browser already signed in and prints a live log of the dashboard's requests (method, path, status, time) and of steps such as a sign-in, a backup, a restore or a settings change. Ctrl-C, closing the terminal or SIGTERM signs out the pages it opened and prints "Signed out; the dashboard is closed." A command that is killed stops renewing its lease, and the dashboard closes within 15 seconds. Several `kinfold dashboard` commands can run at once; each signs out only its own pages. The browser opens at the plain address `http://127.0.0.1:<port>/dashboard/login` on macOS, Linux and Windows, and the page claims the sign-in the running command offered: once, within 60 seconds, and only from the dashboard's own origin. No code or token appears in a URL, a process's arguments or the terminal. `kinfold dashboard --print` prints a link for a script or a browser through an SSH tunnel and keeps the dashboard open for 12 hours or until `kinfold dashboard --close`. An open page whose own command ended shows "Dashboard closed; run `kinfold dashboard` to open it again", even while another `kinfold dashboard` keeps the dashboard open. Capture, recall, central memory and the hub keep running either way, and the dashboard stays signed in through an update's daemon restart.
- 8b108bd: The dashboard is rebuilt. Overview says whether Kinfold is working and what it saved this week, and lists what needs you: failing summaries, an old backup, a release ready to install, or a hub that cannot be reached. Sessions, Memory and Activity are tables sorted, filtered and paged on the daemon; a row opens in a side panel, and the address keeps the page, the filters and the open row. Memory can be sorted by how often each memory was recalled. Activity lists recalls, saved memories, summaries and why they failed, backups, restores, updates, sign-ins and devices joining, kept for 90 days; the daemon log is a download there. Impact shows tokens saved two ways, never added together: measured by the impact test (including "No measurable saving yet" when the difference is within normal variation, and the cost when memory adds tokens), or an "up to" estimate where nothing is measured yet. Settings groups agents and summaries, search, updates, central memory, data and retention, and privacy, and says what each setting does. The dashboard has a dark mode that follows the system. The store moves to schema 18, which records each session's device, each memory's recall count and the summary run that wrote it; records from before the upgrade say they were not recorded.
- c8a84e1: Semantic search runs on a bundled local model by default: all-MiniLM-L6-v2 on your CPU, free, offline, with no memory text leaving the machine. OpenRouter and a local LLM server on loopback (Ollama, LM Studio) are opt-in, picked in the wizard, with `--embeddings`, or on the dashboard's Models page. Search goes through a per-project sqlite-vec index, and switching embedders builds the new index in the background while search keeps the old one. A store that already has OpenRouter vectors stays on OpenRouter until you switch. The program is about 36 MB larger.
- fe1b38b: More observer providers. API providers with your own key: `anthropic-api`, `openai-api`, `gemini-api`, `qwen-api` (DashScope) and `openai-compatible` for any OpenAI-style server, including Ollama and LM Studio on this machine with no key. `goose-cli` runs the observer through a provider key you gave Goose, after the same planted-instruction safety check as Codex and OpenCode. Setup says why an agent's own CLI cannot run its summaries, lists Auggie, which cannot be picked until a live run proves it safe, and takes `--observer-endpoint <url>` for the endpoint providers. The dashboard Models page offers every provider with its key entry and address.
- cf12bcf: One repo is one project. Kinfold keeps each repo's first commit, so a renamed remote, a fork and a clone with no remote merge into the newest key with a remote, on their own, and an upgraded store does this once for the projects it already holds. `kinfold status`, `kinfold watch` and the install output say each merge once. `kinfold project list` shows each key with its counts, `kinfold project split <key>` undoes a merge exactly and keeps the key apart, and `kinfold project merge <old> <into>` joins a folder git cannot match. Merge and split are dry runs without `--yes`, and run on the hub in central mode. A session resumed after its remote was renamed moves to the new key, so the prompt line, the turn end, watch and Sessions name one project.
- cf12bcf: Prompt-time recall answers within the hook's wait on a large, busy store. On a 30,000-memory hub the daemon took 1.5 to 10 s, so the hook gave up and nothing reached the model; it now answers in tens of milliseconds. The prompt's store reads and the dashboard's size, metrics, facets and memory browse run in worker threads with their own read-only connections. The daemon answers by one deadline with what is ready and offers the rest with the next prompt. The search leaves out the wrappers agents add to a prompt (pasted-content tags and their ids, system reminders), ranks your own words before pasted text, and matches on the 8 rarest words its memory holds. Memory in an answer that came too late is offered again once, and counts as sent after a second late answer. Session-start lists put status notes such as "CI run green" after lasting memory and drop them after a day. In the install wizard, a line feed left over from Enter no longer turns a yes or no question to No.
- cf479c0: Updates have three levels, `off`, `notify` and `patch` (the default), set with the wizard, `kinfold install --updates <level>` or the dashboard. At `patch`, a minor or major release is downloaded and checked against `SHA256SUMS` in the background, then offered once at session start (`Kinfold 0.6.0 is ready · 3 changes, 1 breaking · kinfold update to install`) and on the dashboard with its changelog lines and an Install button. Nothing bigger than a patch installs without your yes. `--beta` offers prereleases the same way. Existing installs keep their choice: update check off is `off`, auto-update off is `notify`, anything else is `patch`.
- cf479c0: BREAKING: Update notices no longer go into an agent's model context. Agents with a user line (Claude Code, Codex, Gemini CLI and others) still show them, OpenCode and Kilo Code show them as a toast, and Copilot CLI on its progress line. Cursor, Cline, Kiro, Antigravity and the other agents with no user line leave them to `kinfold status`, the dashboard and `kinfold watch`, which now prints the notice once.
- cab9513: `kinfold watch --debug` shows why each recall came out as it did: how long the hook waited and whether the daemon answered in time, the search (keyword or meaning, the embedding model, the prompt's terms), each candidate with its distance and matched terms and why it was sent or left out, the new memory from other sessions, and the tokens sent. At a Claude Code turn end it prints the turn's usage from the transcript beside the tokens Kinfold added, and it shows each observer run and each session-start pack. `--json` prints one JSON object per event. The daemon records the trace only while a debug watch is connected, keeps it in memory only (the last few hundred events, gone after a restart), and the prompt hook makes no extra request for it.

### Patch Changes

- 8c68a36: A hub re-indexing a large store no longer stops answering. Vectors upkeep used to reconcile the whole vector index on the daemon's thread once a minute, and on a 700 MB encrypted store each pass held it for 2 to 3.5 seconds, so /health, recall and a paired device's dashboard waited. Upkeep now works through the index in windows of observation ids, reading only index ranges, and yields between slices; an old index left after a switch is dropped a chunk at a time. WAL checkpoints now run on a worker of their own: the daemon's connection no longer checkpoints, since the sync at the end of one held its thread for seconds on Windows. The daemon's stall watch now also names the data scan, retention, the observer's work and each request, so a slow step shows in the log by name.
  
  A paired device now tells a busy hub from one it cannot reach. A request that times out says "<hub> is busy and didn't answer in time" and is asked again quietly; a refused connection still says the hub cannot be reached; and a pairing, sign-in or version refusal names that reason. Dashboard pages get a longer wait than recall does.
  
  An expired or missing login is now named when the claude, codex or opencode CLI prints its error as a JSON array, as JSON lines, after a notice line, or as an error event, instead of "its command-line tool stopped with an error".
  
  The claude-cli observer can run on a long-lived token from `claude setup-token`, for a machine where its login keeps expiring. Paste it in the dashboard's Settings, or run `kinfold install --observer-token-stdin`; setup also offers it when the login is failing. Kinfold keeps the token in the system key store and passes it only to the observer's `claude` run, in `CLAUDE_CODE_OAUTH_TOKEN`. `kinfold status` says which login the observer uses, a token that stops working says to run `claude setup-token` again, and uninstall removes it.
- f940f94: The central hub now starts on a Mac that runs the Tailscale app. The app's command acts as a command line only when `TERM` is set, and the daemon runs without one, so every Tailscale lookup failed and the hub never listened. Kinfold now sets `TERM` for every tailscale command, and `kinfold status` says which of three things went wrong: the tailscale command failed (with its first line of output), Tailscale is not running or not signed in, or the command is not installed. A `kinfold central join` that times out now says to look for the firewall prompt on a Mac hub, and `kinfold central serve` and `invite` mention that prompt on macOS.
  
  An observer provider that keeps failing the same way no longer retries at full speed. Kinfold waits a minute after a failure, doubling up to an hour, and starts over after a success, a change to that provider's settings, a passed test in the dashboard or a new key. The claude, codex and opencode observers now read the CLI's own error text (one line, capped and redacted), so an expired login, a missing login and a usage limit each get their own name. A login problem waits the full hour, and its events stay pending, so nothing is lost while it is down. `kinfold status`, the dashboard and `kinfold watch --debug` say which provider is failing and what to do, for example: "claude-cli: the login Kinfold uses has expired; run `claude auth login` in a plain terminal (not one with CLAUDE_CONFIG_DIR set)".
- e0c7cce: Prompt recall carries memory again on a large hub. The new-memory delta and the related search now read at the same time, each on a reader that starts with the daemon, so a slow keyword read no longer costs the new memory and a slow delta no longer costs the related lines. The keyword match filters through a new index (schema 17) instead of each memory's text, about three times faster on a cold 30,000-memory store. The daemon answers right after a start or update: the project merge backfill and the prompt's project lookup no longer run git on the thread that answers. `kinfold size` answers from a kept report on a large store, and a request that times out says so. A running prerelease checks the beta channel for updates, and installing a prerelease turns the beta channel on unless `--no-beta` is given. `kinfold watch --debug` no longer calls a sent memory refused when the previous prompt also found it, and words the term rule as "2 terms matched, 3 needed". The daemon logs what held its thread when anything does for more than a second.
- cab9513: A dashboard session now survives a daemon restart, so pressing Install on the dashboard no longer ends at the sign-in page. Sessions are kept in `dashboard-sessions.json` in the data folder (mode 0600, holding only hashes of the session secrets), keep their 12-hour expiry and sign-out, and are removed on uninstall. With the beta channel on, a newer beta no longer holds back the automatic patch of the running release: the daily check keeps the newest patch of the running version beside the release on offer, installs the patch under `patch`, and still waits for a yes on the beta.
- 86f2852: WSL: every agent's wiring in a linked distro is now tested, with its hooks writing into the Windows memory and its recall line coming from the Windows daemon and its recall toast reading the Windows folder. A new CI job installs the built programs on a Windows runner and runs the Linux build in an Ubuntu WSL2 distro. WSL stays in preview because GitHub's Windows runners refuse mirrored networking, so the hop from the distro to the Windows daemon is checked by fakes only.

## 0.5.0

### Minor Changes

- 20448a8: Everything merged since 0.4.0:
  
  - See what Kinfold recalls. After each prompt the agent shows a line naming the memories Kinfold sent, and a session starts with a short list of recent memories. This goes through `systemMessage` in Claude Code, Codex, Gemini CLI, Qwen Code, Factory Droid, Junie and Auggie, a toast in OpenCode and Kilo Code, a notification in Amp and the progress line in Copilot CLI. `kinfold watch` prints the recall line for every agent.
  - The dashboard has a Sessions page with each turn's prompt, recalled memories, reply and saved memories. Replies are stored in `prompts.reply_text` and follow prompt retention.
  - Metrics shows the tokens Kinfold adds to context, observer tokens and embedding calls. An opt-in impact test (`--holdout`) skips recall on about 1 in 10 Claude Code prompts and compares token use.
  - The observer can be turned off per agent (`--observer <agent>=off`, the wizard or the dashboard), and the wizard's observer question offers only CLIs installed on this machine.
  - `kinfold restore --undo` switches back to the store a restore replaced, keys included, and the Backup page offers the same.
  - Kilo Code captures again, with its own plugin and a recall toast. The plugin Kinfold wrote for Kilo before was refused by Kilo, so nothing was captured from it.
  - Fixes: a second CLI restore refuses at once, uninstall and first install take the update lock, purge removes `turn_usage` rows, late answers are recorded and left out of the counts, and `kinfold status` gives macOS bash users the line to add when there is no `~/.bash_profile`.
  - Migrations 12 and 13. Backups made by this version carry schema 13, which older versions refuse; older backups restore here.
- 20448a8: `kinfold size` and the dashboard Data page break the store down by part: prompts, replies, events, observations, summaries, vectors and other. Past the size warning, a line names the largest part and the setting that trims it, such as `warning: replies are 61% of 2.1 GB; set prompts retention to trim them`. Release notes now carry the version's CHANGELOG.md section, and releases come from changesets and wait for the maintainer's approval.
